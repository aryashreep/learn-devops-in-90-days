💡 ANALOGY: Parallel Realities

Think of workspaces like parallel dimensions:

1. Dimension 1 (dev workspace): Earth-dev. You run tests, spin up small instances. If you destroy this earth, Earth-prod remains untouched.
2. Dimension 2 (prod workspace): Earth-prod. High-security, large databases. Same physics (HCL code), but totally separate existence.

📌 Key Concepts: Workspaces & Environment Isolation

1. Workspace Command Line Interface

# List workspaces
$ terraform workspace list
* default

# Create new workspace
$ terraform workspace new dev
Created and switched to workspace "dev"!

# Switch workspaces
$ terraform workspace select prod
Switched to workspace "prod"!

2. Dynamic Interpolation with `terraform.workspace`

Write configs that inspect the active workspace and adjust values dynamically:

locals {
  instance_types = {
    default = "t2.micro"
    dev     = "t2.micro"
    prod    = "t3.medium"
  }
  
  instance_type = lookup(local.instance_types, terraform.workspace, "t2.micro")
}

resource "aws_instance" "web" {
  ami           = "ami-08c40ec9ead489470"
  instance_type = local.instance_type
  
  tags = {
    Name        = "WebServer-${terraform.workspace}"
    Environment = terraform.workspace
  }
}

3. Project Layout Strategies

Workspaces use the **same code** with different state targets. In complex production environments, it is recommended to use **separate directory hierarchies** (dev/, prod/) instead to isolate different versions of modules.

🔄 Compare: Workspaces vs Folder splitting

Workspaces (Same Code)

Pros: DRY, quick env switching.
Cons: High risk of typos (applying dev updates to prod by mistake). Code versions must remain identical.

VS

Separate Folders (dev/, prod/)

Pros: Strict safety boundary, can test different module versions in dev.
Cons: Code duplication, more files to manage.

⚠ COMMON MISCONCEPTIONS
  • Myth: Workspaces protect you from destroying resources in other environments.
  • Reality: No! While states are isolated, a developer who forgets to run `terraform workspace select dev` might accidentally run `terraform destroy` in the active `prod` workspace. Double-check your active workspace via terraform workspace show first!
