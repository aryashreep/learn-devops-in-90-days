📌 Key Concepts: Syntax, Providers & Dependencies

1. HCL Block Structure

#  "" "" {
#    = 
# }

resource "local_file" "pet" {
  filename = "/root/pets.txt"
  content  = "We love pets!"
}

2. Provider Pinning

Always tell Terraform the exact source and version of the plugin you want to use:

terraform {
  required_providers {
    docker = {
      source  = "kreuzwerker/docker"
      version = "2.21.0"
    }
  }
}

provider "docker" {
  # Configuration options
}

3. Implicit vs Explicit Dependencies

Implicit: Terraform auto-detects dependency when a resource references an attribute of another resource.

resource "aws_eip" "myeip" {
  instance = aws_instance.web.id  # Implicit dependency on 'web'
}

Explicit: When resources don't share data references but one must still build first, use `depends_on`:

resource "aws_instance" "web" {
  ami           = "ami-xyz"
  instance_type = "t2.micro"
  
  depends_on = [aws_s3_bucket.data_bucket] # Explicit dependency
}
🔄 Compare: Implicit vs Explicit

Implicit Dependency

Uses variable references (e.g., id = aws_vpc.main.id). Clean, automatic, preferred.

VS

Explicit Dependency

Uses depends_on = [...] argument. Used when dependencies are logical/operational, not data-based.

📖 REAL-WORLD EXAMPLE: Docker Web Deployment

Scenario: You want to deploy an Nginx web server container via Docker.

Solution: The docker container requires a docker image first. We build an implicit dependency cycle:

resource "docker_image" "nginx_img" {
  name         = "nginx:latest"
  keep_locally = false
}

resource "docker_container" "nginx_web" {
  image = docker_image.nginx_img.image_id # Implicitly depends on nginx_img
  name  = "tutorial-web-server"
  ports {
    internal = 80
    external = 8080
  }
}
⚠ COMMON MISCONCEPTIONS
  • Myth: You can declare resource blocks in any order you want in HCL files.
  • Reality: Yes, HCL is declarative, meaning the written order of blocks in files does NOT affect creation order. Terraform reads all blocks, draws a dependency graph, and creates them in the mathematically correct order.
  • Myth: `depends_on` makes Terraform apply faster.
  • Reality: No, `depends_on` forces resources to run sequentially, which can actually slow down deployments if used excessively where parallel creation is possible.
▶ TRY IT YOURSELF

1. Install docker on your local system: sudo apt-get install docker.io -y.
2. Give current user permission to docker socket: sudo chown $USER /var/run/docker.sock.
3. Write the provider and docker container code in a file named main.tf.
4. Run terraform init, terraform plan, and terraform apply.

📝 QUICK SUMMARY
  • Providers translate HCL calls to real API commands (AWS, Docker).
  • HCL identifiers consist of blocks, labels, and arguments.
  • Implicit dependencies occur automatically by referencing resource outputs.
  • Explicit dependencies must be declared with `depends_on = [resource.name]`.
