📂 Key Directories & Files

Standard folder structure for modular infrastructure projects:

project-root/
├── main.tf (Invokes modules)
├── variables.tf
├── outputs.tf
└── modules/
    └── web_server/ (Child module)
        ├── main.tf (Child resource declarations)
        ├── variables.tf (Defines child input variables)
        └── outputs.tf (Exposes child properties to root)
📌 Key Concepts: Child Modules & Interfaces

1. The Child Module (modules/web_server/main.tf)

variable "instance_type" { type = string }
variable "server_name"   { type = string }

resource "aws_instance" "server" {
  ami           = "ami-08c40ec9ead489470"
  instance_type = var.instance_type
  
  tags = {
    Name = var.server_name
  }
}

output "instance_id" {
  value = aws_instance.server.id
}

2. Invoking the Module from Root (main.tf)

module "dev_server" {
  source        = "./modules/web_server" # Local source path
  instance_type = "t2.micro"
  server_name   = "Dev-Server"
}

module "prod_server" {
  source        = "./modules/web_server"
  instance_type = "t2.medium"
  server_name   = "Prod-Server"
}

output "dev_id" {
  value = module.dev_server.instance_id # Access child output
}

3. Module Version Pinning

When downloading modules from registries, always specify version restrictions to avoid unwanted updates:

module "vpc" {
  source  = "terraform-aws-modules/vpc/aws"
  version = "3.14.0" # Version Pinning

  name = "my-vpc"
  cidr = "10.0.0.0/16"
}
🔄 Compare: local source vs registry source

Local Modules

Relative folder paths (e.g., ./modules/web). Used for custom configurations developed internally.

VS

Registry Modules

Hosted online (e.g., Terraform Registry). Verified solutions provided by vendors (AWS, HashiCorp).

⚠ COMMON MISCONCEPTIONS
  • Myth: You can directly access child module resource properties from the root configuration.
  • Reality: No! Modules act as black boxes. The only way to access a resource property inside a child module is by explicitly declaring it in the child module's outputs.tf, and then calling it using module.name.output_name in the root.
▶ TRY IT YOURSELF

1. Create a subfolder structure: modules/local_file_generator.
2. Inside the module, write a file generator with input path and content variables.
3. Invoke this module from your root main.tf twice.
