📌 Key Concepts: Input, Outputs & Data Sources

1. Input Variables in variables.tf

variable "instance_type" {
  type        = string
  default     = "t2.micro"
  description = "Size of our AWS EC2 instance"
}

variable "env_tags" {
  type    = map(string)
  default = {
    dev  = "development"
    prod = "production"
  }
}

2. Output Variables and Sensitivity

Use outputs to print key values or pass them to other modules. Mark sensitive variables to prevent console exposure:

output "public_ip" {
  value = aws_instance.my_server.public_ip
}

output "db_password" {
  value     = aws_db_instance.db.password
  sensitive = true  # State file still tracks it, but hides it on CLI
}

3. Data Sources

Read resources created outside of your current Terraform workspace:

data "aws_ami" "ubuntu" {
  most_recent = true
  owners      = ["099720109477"] # Canonical
  
  filter {
    name   = "name"
    values = ["ubuntu/images/hvm-ssd/ubuntu-jammy-22.04-amd64-server-*"]
  }
}

resource "aws_instance" "my_server" {
  ami           = data.aws_ami.ubuntu.id  # Use fetched data
  instance_type = var.instance_type
}

4. HCL Built-in Functions

  • lookup(map, key, default): Extracts a value from a map by key.
  • element(list, index): Extracts a single item from a list at specified index.

📖 REAL-WORLD EXAMPLE: Environment Selector

Scenario: Select `t2.micro` for Dev, but `t2.medium` for Prod.

Solution: Use a conditional variable evaluation:

variable "env" {
  type    = string
  default = "dev"
}

resource "aws_instance" "app_server" {
  ami           = "ami-08c40ec9ead489470"
  instance_type = var.env == "prod" ? "t2.medium" : "t2.micro"
  
  tags = {
    Name = "AppServer-${var.env}"
  }
}
⚠ COMMON MISCONCEPTIONS
  • Myth: Marking an output `sensitive = true` encrypts the value in the state file.
  • Reality: No! It ONLY hides the value in CLI output messages. The plaintext sensitive value is still stored in plaintext JSON inside the terraform.tfstate file. You must protect the state file directly.
