Bhai, Aaj Kya Seekhenge?

Aaj hum Git ke "Panic Buttons" master karenge. **Reset** (Hard/Soft/Mixed) ka real difference, **Revert** vs Reset, aur deleted commits ko wapis lane ka magic tool: **git reflog**. Saath hi, **Cherry-pick** aur **Stash** jaise surgical tools bhi explore karenge.

🎯 LEARNING OBJECTIVES
  • Recover: Use `git reflog` to rescue "lost" commits.
  • Undo: Master `reset` vs `revert` for local and public fixes.
  • Surgical: Cherry-pick specific commits from one branch to another.
  • Save: Temporarily store messy work with `git stash`.

💡 Kyu Seekhein? Kyunki real world mein galtiyan hongi. Ek pro DevOps engineer wahi hai jo system ko recover kar sake!

💡 ANALOGY: The Time Machine vs The Undo Button

1. Reset: Time machine mein baith kar peeche chale gaye (History badal di).
2. Revert: Ek naya commit kiya jo purani galti ko theek karta hai (History intact).
3. Reflog: CCTv footage—tumne kahan-kahan pair rakha, sabka record!
4. Stash: Kapde (code) cupboard mein thodi der ke liye rakh diye.

📌 Key Concepts: Reset vs Revert

Reset

"Commit ko history se mita dena. Dangerous!"

  • --soft: Files staging mein rahengi.
  • --hard: Sab kuch saaf!
  • Best for: Private/Local work.
VS

Revert

"Galti ko opposite commit se theek karna. Safe!"

  • History delete nahi hoti.
  • New commit create hota hai.
  • Best for: Public/Shared branches.
✂ Surgical Tools

Cherry-Pick & Stash

  • git cherry-pick [SHA]: Kisi doosri branch se ek specific fruit (commit) utha kar apni branch pe lana.
  • git stash: "Arey koi guest aa gaya!"—Messy code chhupao, clean slate pe kaam karo, baad mein `stash pop` karlo.
