The Networking Handbook

From Bits and Frames to VPCs and Load Balancers

1. What is Networking?

A network is formed when two or more systems connect to communicate. Think of it like a Postal Service for computers. You need roads (cables), addresses (IPs), and envelopes (packets).
Why it matters: In DevOps, "Infrastructure as Code" means defining networks using software. If the network fails, your app is unreachable, no matter how good your code is!
  • Nodes: Any device (server, laptop, router) on the network.
  • Links: The physical or wireless connections.
  • Protocol: The rules of the conversation (e.g., TCP/IP).
  • Topology: The layout (Star, Bus, Mesh).

2. OSI vs. TCP/IP (Practical View)

Models split networking into layers, like an Assembly Line. Each layer has a specific job.
  • Layer 7 (Application): HTTP, FTP, SSH (Where apps live).
  • Layer 4 (Transport): TCP/UDP ports (Reliability).
  • Layer 3 (Network): IP addresses and Routing.
  • Layer 2 (Data Link): MAC addresses and Switches.
  • Layer 1 (Physical): Cables and electricity.
# Layer 3 Check (Can I see the machine?) ping 8.8.8.8 # Layer 4 Check (Is the door open?) telnet google.com 80

3. IP Addresses & Subnetting

The Building Analogy: An IP address is the building's street address. A Public IP is the front door (routable on the internet). A Private IP is like an internal extension (e.g., 10.x.x.x).
Subnetting is slicing a large network into smaller slices. CIDR notation (like /24) tells you how big the slice is.
  • /32: Just 1 single IP.
  • /24: 254 usable IPs.
  • /16: 65,000+ usable IPs.
Lower CIDR = More IPs. Higher CIDR = Fewer IPs. Confusion mat paalo!

4. DNS: The Internet's Phonebook

Computers only know IPs. DNS translates "google.com" into 142.250.x.x. "It's always DNS" is a meme because when it breaks, everything feels broken!
  • A Record: Name to IPv4.
  • CNAME: Name to another Name (Alias).
  • TTL (Time to Live): How long the record is cached.
# DNS Lookup nslookup google.com dig google.com

5. TCP vs. UDP

Communication Styles: TCP: Like a Phone Call. Reliable, ordered, and acknowledged (3-Way Handshake).
UDP: Like a P.A. System. Fast, but unreliable. Use for streaming or gaming.
# Test connection with netcat nc -zv

6. Firewalls & NAT

A Firewall is a security guard. It follows Inbound/Outbound rules. In the cloud, we call them Security Groups.
NAT (Network Address Translation): Allows private servers to share one Public IP to access the internet. Like an office receptionist handing out mail.

7. Load Balancing & Proxies

  • L4 Load Balancer: Distributes based on IP/Port (Fast).
  • L7 Load Balancer: Distributes based on content/URL (Smart).
  • Reverse Proxy: Sits in front of your server to handle SSL and Caching (Bodyguard).

8. VPC & Kubernetes Networking

VPC: Your own private slice of the cloud data center.
K8s Networking: Pods are ephemeral! Never use Pod IPs; always talk via Services (Stable DNS names).

9. Troubleshooting Funnel

Sabse pehle bottom (Physical/IP) se shuru karo, fir Application tak jaao.
  1. Is the cable plugged in? (Cloud: Is instance running?)
  2. Can I ping the Gateway?
  3. Is the Firewall/Security Group blocking the port?
  4. Is the service actually running? (curl -v)
