Volumes PV PVC & Storage Classes

Day 58: Storage Persistence & Claims ☸️

Naked
"Wake up, all data in the database disappears when the container is restarted! Can't we save data permanently in Kubernetes?"
"You can Golu! Containers are ephemeral by default. K8s uses Persistent Volumes (PV) and Persistent Volume Claims (PVC) for permanent data storage. And we use Storage Classes to automate storage provisioning!"
Section

1. Learning Objectives

Kubernetes will understand storage options, allocate physical disks, and assign stable space to applications.

  • Volumes: Ephemeral container volumes vs Persistent volumes.
  • PV & PVC: Claiming storage abstractions.
  • Storage Classes: Dynamic storage provisioning on cloud (AWS EBS, etc.).
2. Analogy & Mental Model

Think of storage as **allocating real-estate**:

  • Persistent Volume (PV - The Land): A physical piece of land set aside by an administrator.
  • Persistent Volume Claim (PVC - Rental Application): A developer's application specifying: "I need 5GB of land with read-write access."
  • Storage Class (Real Estate Agent): Automatically finds, buys, and assigns the land on-demand when the developer asks for it, so you don't have to pre-allocate land manually.
3. Did You Know?
RWO
ReadWriteOnce - volume mounted by single node only
Retain
Reclaim policy that keeps PV data safe even if PVC is deleted
Dynamic
StorageClasses provision physical disks on cloud automatically
4. PV & PVC Manifests

Persistent Volume: pv.yaml

apiVersion: v1
kind: PersistentVolume
metadata:
  name: local-pv
spec:
  capacity:
    storage: 5Gi
  accessModes:
    - ReadWriteOnce
  persistentVolumeReclaimPolicy: Retain
  hostPath:
    path: "/mnt/data"

Persistent Volume Claim: pvc.yaml

apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: local-pvc
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 2Gi
5. Key Concepts & Pod Mounting

Here is how a Pod mounts the PVC: pod-with-storage.yaml

spec:
  containers:
  - name: my-db
    image: mysql:latest
    volumeMounts:
    - name: db-data
      mountPath: /var/lib/mysql
  volumes:
  - name: db-data
    persistentVolumeClaim:
      claimName: local-pvc
6. Compare: Static vs. Dynamic Provisioning
Static Provisioning
  • Admin creates PV manually first
  • Dev writes PVC to bind to it
  • Tedious, manual scaling
  • Wastes space if claims don't match
VS
Dynamic Provisioning
  • Admin defines a StorageClass
  • Dev requests storage in PVC
  • StorageClass automatically spins up disk (e.g. AWS EBS)
  • Zero administrator intervention
7. Real-World Troubleshooting Example

Incident: Pod stays stuck in Pending state with volume error.

Debugging Process:

# Check Pod events
kubectl describe pod pod-with-storage

# Check PVC binding status
kubectl get pvc

Commonly, the PVC is stuck in Pending because there are no PVs matching the access mode or requested size, or the StorageClass provisioner is failing in the backend cloud network.

8. Common Misconceptions
  • ❌ Myth: Deleting a PVC deletes the physical disk instantly.
  • ✔️ Reality: Depends on reclaim policy. If set to Retain, K8s keeps the PV intact. If set to Delete, the physical disk is deleted.
  • ❌ Myth: HostPath storage is safe for production.
  • ✔️ Reality: HostPath binds to a specific physical node. If the Pod schedules on a different node next time, it won't find the data! Always use cloud volumes (EBS, NFS) for prod.
9. Try It Yourself

Verify storage properties using commands:

# List active PVs
kubectl get pv

# List active PVCs
kubectl get pvc

# Check volume mount details on pod
kubectl describe pod pod-with-storage
10. Quick Summary
  • Persistent Volumes separate storage resources from pod Lifecycles.
  • PVC claims storage; bound automatically.
  • StorageClasses provision volume disks dynamically.
