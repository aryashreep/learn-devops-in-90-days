1. Learning Objectives

You will understand the K8s declarative system, check the YAML manifests, and launch your first Pod.

  • Imperative vs Declarative: `kubectl run` vs `kubectl apply -f`.
  • Pod Manifest Structure: apiVersion, kind, metadata, spec.
  • Pod operations: logs checking, port-forwarding, execution.
2. Analogy & Mental Model

Think of a Pod as a Pea Pod:

  • The Pod is the outer shell.
  • The containers inside are the peas.
  • All peas inside share the same water and environment inside the shell.
3. Did You Know?
IP
Every Pod gets its own unique IP address in the cluster
pause
A special pause container manages networking namespaces in Pods
localhost
Containers inside the same Pod communicate via localhost
4. Key YAML Structure (The 4 Pillars)

Every Kubernetes manifest contains 4 root fields:

  • 📝 apiVersion - API version of the object (e.g., v1 for Pods).
  • 📝 kind - Type of resource (e.g., Pod).
  • 📝 metadata - Identification (name, labels, namespace).
  • 📝 spec - Desired configuration state (containers, volumes).
5. Key Concepts & Pod Specification

Here is a basic Pod manifest: pod.yaml

apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod
  labels:
    app: web
spec:
  containers:
  - name: nginx
    image: nginx:alpine
    ports:
    - containerPort: 80
6. Compare: Imperative vs. Declarative
Imperative (Tell K8s WHAT to do)
kubectl run nginx --image=nginx
  • Fast, quick testing in CLI
  • Hard to track changes over time
  • Not suited for production pipelines
VS
Declarative (Declare the STATE)
kubectl apply -f pod.yaml
  • Stored in version control (Git)
  • Self-documenting infrastructure
  • Allows easy rolling updates/audits
7. Real-World Troubleshooting Example

Incident: A pod goes into CrashLoopBackOff state.

Debugging Process:

# Check status details
kubectl get pods

# View events to find configuration problems
kubectl describe pod nginx-pod

# View container output logs
kubectl logs nginx-pod

Often, it is due to an application script exiting immediately or a missing environment variable.

8. Common Misconceptions
  • ❌ Myth: Pods are permanent VM-like instances.
  • ✔️ Reality: Pods are ephemeral. They are destroyed and recreated with new IPs on reschedule events. Do not write state inside them.
  • ❌ Myth: You should deploy bare (naked) pods.
  • ✔️ Reality: Always wrap Pods in controllers like Deployments so they are replaced if they fail.
9. Try It Yourself

Run a test Pod, check logs, and forward port 8080 to test locally:

# Apply manifest
kubectl apply -f pod.yaml

# Check logs
kubectl logs nginx-pod

# Port forward to local port 8080
kubectl port-forward nginx-pod 8080:80

# Clean up
kubectl delete pod nginx-pod
10. Quick Summary
  • Pods are the basic execution unit wrapping containers.
  • A Pod gets a cluster-wide unique IP.
  • Declarative manifests are standard practice in DevOps.
