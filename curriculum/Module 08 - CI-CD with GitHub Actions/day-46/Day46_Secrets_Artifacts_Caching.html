Secrets are like placing valuables in a bank vault (GitHub Settings). During pipeline runs, the vault opens briefly to hand the key to the runner. Caching is like downloading dependencies to a locker—next run, you grab it from the locker instead of driving back to the store. Artifacts are the final package you ship out.

⚙️ Main Content

1. GitHub Secrets

Store API keys, passwords, and tokens under Settings -> Secrets and Variables -> Actions. GitHub hides them from logs. Even if you run echo $SECRET_VALUE, the logs will show ***.

2. Caching vs. Artifacts

  • Caching: Saves files between different workflow runs (e.g. node_modules, pip cache) to optimize speed.
  • Artifacts: Saves outputs of the current run (e.g. compiled binaries, test coverage reports) to share between jobs or download.

3. Cache Keying

To avoid stale caches, key the cache with a hash of your project lockfile: hashFiles('**/package-lock.json').

⌨️ Try It Yourself
# YAML snippet for dependency caching and artifact upload:
- name: Cache dependencies
  uses: actions/cache@v4
  with:
    path: ~/.npm
    key: ${{ runner.os }}-node-${{ hashFiles('**/package-lock.json') }}
- name: Run Tests
  run: npm ci && npm test
- name: Save Build
  uses: actions/upload-artifact@v4
  with:
    name: build-assets
    path: dist/
