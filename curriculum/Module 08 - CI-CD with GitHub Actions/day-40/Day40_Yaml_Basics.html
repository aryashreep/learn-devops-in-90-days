\U0001f3af Why YAML for DevOps?
  • GitHub Actions, GitLab CI, Ansible, Kubernetes — all use YAML
  • Human-readable: indentation-based, koi braces nahi
  • Comments support (# se), anchors, multi-line strings
  • Portable: language-agnostic, har platform pe support

\u2328\ufe0f YAML in GitHub Actions
name: CI Workflow
on: [push]  # trigger event

env:         # key-value
  NODE_VERSION: '18'

jobs:        # nested structure
  build:     # job name
    runs-on: ubuntu-latest  # string
    steps:                  # list
      - name: Checkout
        uses: actions/checkout@v4
      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
      - name: Install
        run: npm ci
      - name: Test
        run: npm test

Key points: indentation = 2 spaces (no tabs!), colon ke baad space, lists start with dash-space

\U0001f4dd Common YAML Pitfalls
  • \u274c then character: YAML allows only spaces
  • \u274c Inconsistent indentation: Har level pe same spaces
  • \u274c Missing space after colon: key:value is invalid
  • \u274c Unquoted special chars: yes/no = boolean, use quotes
  • \u2705 Tip: Use python3 -c "import yaml; yaml.safe_load(open('file.yml'))" to validate
