💡 Mental Model

A Composite Action is like creating a custom tool (a multi-tool screwdriver). A Reusable Workflow is like hiring an entire team of contractors to do a job—they come with their own toolboxes (jobs, runners) and carry out a multi-step project based on inputs you provide.

📈 Did You Know?
DRY Principle

Don't Repeat Yourself: maintain one template workflow instead of copies in dozens of repos.

workflow_call

The special trigger event that registers a workflow as a reusable template.

Central Security

Update central scripts once, and all microservices instantly inherit the security patches.

📁 Core Concepts & Directories
  • Reusable workflows are triggered by the `on: workflow_call:` event.
    • \n
  • Called workflows reside in either the local repository or a public/private remote repository.
    • \n
  • Pin calling syntax to a specific commit SHA or version tag (e.g. `@v1.0.0`) for safety.
⚙️ Main Content

1. Reusable Workflows vs. Composite Actions

  • Reusable Workflows: Written in YAML, can contain multiple jobs, define their own runners. Triggered by workflow_call.
  • Composite Actions: Group multiple shell commands/steps inside a single action block. Cannot define multiple jobs or runners; they execute on the caller's runner.

2. Declaring a Reusable Workflow

name: Reusable Workflow
on:
  workflow_call:
    inputs:
      env:
        required: true
        type: string
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - run: echo "Deploying to ${{ inputs.env }}"
⌨️ Try It Yourself
# Try calling a reusable workflow inside a caller YAML file:
jobs:
  call-workflow:
    uses: my-org/central-repo/.github/workflows/deploy-template.yml@v1
    with:
      env: staging
    secrets: inherit

1. Which event trigger must be defined in the 'on' block of a workflow to make it reusable by other workflows?
A) workflow_dispatch\nB) workflow_call\nC) repository_dispatch\nD) workflow_run
2. What is the key limitation of a Composite Action compared to a Reusable Workflow?
A) Composite Actions cannot run shell scripts.\nB) Composite Actions cannot define multiple separate jobs or run on independent runners; they operate within a caller's single job runtime.\nC) Composite Actions cannot take inputs.\nD) Composite Actions are deprecated.

Answer Key:

1: B (workflow_call triggers reusable workflows), 2: B (Composite actions are restricted to a single job/runner context)
