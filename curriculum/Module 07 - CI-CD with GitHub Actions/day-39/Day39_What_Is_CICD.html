Think of CI/CD like an automated car assembly line. CI is the automated quality check station that inspects every new part (code change). CD is the delivery truck that automatically delivers the finished car to the showroom.

📁 Core Concepts & Directories
  • Continuous Integration (CI): Code changes are merged to main, triggering automated builds and tests.
    • \n
  • Continuous Delivery (CD): Code is automatically packaged and ready to deploy to staging.
    • \n
  • Continuous Deployment (CD): Every change passing tests is deployed to production automatically.
⚙️ Main Content

1. The Core Stages of CI/CD

  • Source Stage: Triggered when code is pushed or a PR is created.
  • Build Stage: Compile code, download dependencies, build container images.
  • Test Stage: Run unit tests, integration tests, static code analysis.
  • Deploy Stage: Deploy the artifact to staging, testing, or production environments.

2. Why CI/CD Matters

Without CI/CD, developers manually build, test, and upload code (via FTP or SSH) once a month. This leads to 'Integration Hell' where different branches conflict and break the system.

⌨️ Try It Yourself
# Imagine a simple deploy script deploy.sh:
#!/bin/bash

npm run build
echo "Running tests..."
npm test
echo "Deploying to production..."
scp -r ./dist/ server:/var/www/html

1. What is the key difference between Continuous Delivery and Continuous Deployment?
A) Continuous Delivery requires manual approval to deploy to production, while Continuous Deployment is fully automated.\nB) Continuous Deployment does not run automated tests.\nC) Continuous Delivery is for frontend, Continuous Deployment is for backend.\nD) There is no difference; they are identical.
2. What does Continuous Integration primarily focus on?
A) Registering domain names\nB) Automating code merging, builds, and test execution\nC) Purchasing cloud servers\nD) Designing database schemas

Answer Key:

1: A (Continuous Delivery has a manual step for production; Continuous Deployment is fully automated), 2: B (Automating code merging, builds, and test execution)
