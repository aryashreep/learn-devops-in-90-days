Bhai, Aaj Kya Seekhenge?

Aaj hum team collaboration ke rules master karenge. **Pull Request (PR)** ka asali workflow, **Merge Conflicts** ko handle karne ka dimaag, aur professional branching strategies jaise **GitHub Flow** aur **Trunk-based development**.

🎯 LEARNING OBJECTIVES
  • Workflow: Master the Pull Request (PR) process for team review.
  • Conflict Resolution: Learn to read and fix `<<< === >>>` markers.
  • Safety: Understand why `push --force-with-lease` is better than `--force`.
  • Strategy: Choose the right branching strategy for your project.

💡 Kyu Seekhein? Kyunki production code bina peer review ke kabhi merge nahi hona chahiye!

🛣 Branching Strategies

GitHub Flow

"Feature branches banao, PR create karo, merge karo. Simple and standard!"

  • Har change ke liye nayi branch.
  • PR review mandatory hai.
  • Best for: Open source & standard projects.
VS

Trunk-Based

"Seedha `main` pe kaam karo (short-lived branches). Continuous Integration ka asli maza!"

  • Choti branches, jaldi merge.
  • High automation ki zarurat hai.
  • Best for: High-velocity DevOps teams.
▶ TRY IT YOURSELF

1. git checkout -b my-feature

2. git push origin my-feature (Create PR on GitHub)

3. git pull origin main (Sync before merge)
