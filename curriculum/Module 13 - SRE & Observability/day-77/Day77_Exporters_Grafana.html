🔌 The Exporters

Exporters translate third-party stats into the Prometheus format at /metrics. Two essentials:

Host metrics                  Container metrics
┌────────────────┐            ┌────────────────┐
│  NODE EXPORTER │ :9100      │   cAdvisor     │ :8080
│  CPU / RAM     │            │  per-container │
│  Disk / Net    │            │  CPU / Memory  │
└───────┬────────┘            └───────┬────────┘
        │  /metrics                   │  /metrics
        └──────────┬──────────────────┘
                   ▼
           ┌───────────────┐
           │  PROMETHEUS   │ :9090
           └───────┬───────┘
                   ▼
           ┌───────────────┐
           │   GRAFANA     │ :3000
           └───────────────┘
💻 Node Exporter — Host Stats
docker run -d --name node_exporter -p 9100:9100 \
  --net="host" --pid="host" \
  -v "/:/host:ro,rslave" \
  quay.io/prometheus/node-exporter:latest \
  --path.rootfs=/host

# Verify
curl localhost:9100/metrics | grep node_cpu_seconds_total

Metrics exposed: node_cpu_seconds_total, node_memory_*, node_filesystem_*, node_network_* and more.

🐳 cAdvisor — Container Stats
docker run -d --name cadvisor -p 8080:8080 \
  --volume=/:/rootfs:ro \
  --volume=/var/run:/var/run:ro \
  --volume=/sys:/sys:ro \
  --volume=/var/lib/docker/:/var/lib/docker:ro \
  gcr.io/cadvisor/cadvisor:latest

Metrics exposed: container_cpu_usage_seconds_total, container_memory_usage_bytes, container_network_receive_bytes_total — per container, keyed by name.

⚙️ Scrape Both in prometheus.yml
scrape_configs:
  - job_name: 'node'
    static_configs:
      - targets: ['localhost:9100']
  - job_name: 'cadvisor'
    static_configs:
      - targets: ['localhost:8080']

# Reload without restart
kill -HUP $(pgrep prometheus)
# or with Docker:
docker kill -s HUP prometheus

Jagu's Tip: You can hot-reload configs with SIGHUP — no downtime needed!

📊 Grafana — The Dashboard Layer
docker run -d --name grafana -p 3000:3000 grafana/grafana
# Open http://localhost:3000 → login admin/admin

# 1. Add Data Source: Configuration → Data Sources → Prometheus
#    URL: http://localhost:9090   →  Save & Test

# 2. Import Dashboard: Dashboards → Import → ID: 1860  → Load
#    Select the Prometheus data source → Import

Panel Types: Time series, Stat, Gauge, Bar gauge, Table — pick what tells the story best.

⚖️ Compare: RED vs USE Methods

RED — Services

  • Rate — requests per second
  • Errors — failed requests
  • Duration — latency (p95, p99)
  • Built for microservices & APIs

USE — Hosts

  • Utilization — % busy
  • Saturation — queue depth / backlog
  • Errors — device errors
  • Built for infrastructure (CPU, disk, NIC)

Use both — RED for your apps, USE for your machines.

🌍 Real-World Example

Netflix-style SRE: When Netflix notices a spike in buffering, engineers don't guess. They open a Grafana dashboard showing streaming requests per second (RED), overlay the CDN node utilization (USE), and spot exactly which region's cache is saturated. A dashboard that combines both methods turns a 2-hour firefight into a 5-minute fix.

# The exact panel query for "CPU saturation"
sum(rate(node_cpu_seconds_total{mode!="idle"}[5m])) / count(node_cpu_seconds_total{mode="idle"}) * 100
🚫 Common Misconceptions
  • "Dashboards must be huge." No — one focused row per service beats 40 rows nobody reads.
  • "Node Exporter = full monitoring." It's host-only; services and containers need their own exporters.
  • "Grafana is only for Prometheus." Grafana unifies 50+ data sources: Loki, CloudWatch, MySQL, and more.
  • "cAdvisor is production-grade." It's great for single hosts; for clusters use kubelet's built-in /metrics/cadvisor.

⚡ Quick Summary
  • Node Exporter (:9100) → host metrics; cAdvisor (:8080) → container metrics.
  • Add jobs to prometheus.yml, reload with SIGHUP.
  • Grafana (:3000) connects to Prometheus as a data source.
  • Import community dashboards (ID 1860) or build custom panels.
  • Use RED for services and USE for hosts.
  • A good dashboard answers questions — not just shows lines.
