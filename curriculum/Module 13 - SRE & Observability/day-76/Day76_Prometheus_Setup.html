🧠 The Three Pillars of Observability

Observability = the ability to ask any new question about your system without shipping new code. It rests on three pillars:

┌────────────────────────────────────────────────┐
│           OBSERVABILITY (LGTM Stack)           │
├───────────────┬───────────────┬────────────────┤
│  METRICS      │  LOGS         │  TRACES        │
│  "Is it       │  "What        │  "Which        │
│   slow/down?" │  happened?"   │   path?"       │
│  Prometheus   │  Loki         │  OTel/Tempo    │
└───────────────┴───────────────┴────────────────┘

Golu's Rule: Metrics alert you, logs explain you, traces connect the dots across services.

🏗️ Why Prometheus PULLs

Unlike old-style agents that push data, Prometheus scrapes HTTP endpoints on a schedule. Every exporter exposes /metrics:

Prometheus                 Targets (exporters)
┌──────────────┐  scrape   ┌──────────────┐
│  TSDB        │ ────────→ │ App   :8080  │
│  Rules       │  HTTP     │ Node  :9100  │
│  Alertmanager│ ────────→ │ cAdvisor:8080│
│  PromQL UI   │           └──────────────┘
└──────────────┘  "pull" = YOU control timing

Why pull wins: health of the target is instantly visible (up metric), no daemon to install, and you never get flooded by 10,000 agents pushing at once.

🔢 Metric Types
  • Counter — only goes up, resets on restart. Perfect for total requests. Query with rate().
  • Gauge — goes up and down. Perfect for temperature, memory, connections.
  • Histogram — counts observations in buckets + sum + count. Perfect for latency.
  • Summary — client-side quantiles (p50, p99). Use sparingly — expensive.
# A counter example from node_exporter
node_network_receive_bytes_total{device="eth0"}   # counter → use rate()
node_memory_MemFree_bytes                         # gauge → use directly
http_request_duration_seconds_bucket{le="0.5"}    # histogram bucket
⚖️ Compare: Monitoring vs Observability

Monitoring (Reactive)

  • Pre-built dashboards for known problems.
  • "Is the server down?" — yes/no alerts.
  • You know what to look for.
  • Blind to the unexpected.

Observability (Exploratory)

  • Rich telemetry to answer NEW questions.
  • "Why is p99 latency spiking at 3 AM?"
  • You can explore metrics, logs & traces.
  • Catches the unexpected outage.

/var/lib/prometheus/
└── metrics2/             # Time-Series Database (TSDB) storage

~/prom/                    # Your local lab project (this module)
├── prometheus.yml
└── promtool              # Validator binary (check config)
🛠️ Try It Yourself
# 1. Start Prometheus (Docker)
docker run -d --name prometheus -p 9090:9090 \
  -v $PWD/prometheus.yml:/etc/prometheus/prometheus.yml \
  prom/prometheus

# 2. Validate your config first
promtool check config prometheus.yml

# 3. Open the UI and run PromQL
#    http://localhost:9090  →  "Execute"
up                          # 1 = target healthy
prometheus_tsdb_head_series  # how many time series we store

Jagu's Tip: Always run promtool check config before restarting Prometheus — a typo in YAML = silent outage!

🌍 Real-World Example

SoundCloud 2012: Prometheus was born because SoundCloud's Nagios couldn't keep up with thousands of microservices. Their SRE team needed instant answers like "which of my 3,000 services has error rates above 1%?" — an impossible question with classic monitoring. Prometheus's pull model + PromQL made it a one-line query:

sum(rate(http_requests_total{status=~"5.."}[5m])) by (service) > 0.01

Today, companies like DigitalOcean, GitLab, and Grafana Labs run Prometheus as their core metrics backbone.

🚫 Common Misconceptions
  • "Prometheus can't scale." False — it scales with federation, sharding, and Thanos/Mimir for long-term storage.
  • "Metrics alone = observability." No — you need logs and traces too for full answers.
  • "Push is better than pull." For batch jobs push works, but pull gives free health checks and easier debugging.
  • "More dashboards = more observability." No — dashboards without runbooks are just pretty wallpapers.
⚡ Quick Summary
  • Observability = metrics + logs + traces working together.
  • Prometheus pulls metrics over HTTP from exporters.
  • Four metric types: Counter, Gauge, Histogram, Summary.
  • prometheus.yml defines global settings and scrape jobs.
  • PromQL queries like up and rate() answer "is it healthy?" and "how fast is it changing?".
  • Validate everything with promtool check config.
