🐳 docker-compose.yml — The Heart
services:
  node-exporter:
    image: quay.io/prometheus/node-exporter:latest
    command: --path.rootfs=/host
    ports:
      - "9100:9100"
    volumes:
      - /:/host:ro,rslave

  cadvisor:
    image: gcr.io/cadvisor/cadvisor:latest
    ports: ["8080:8080"]
    volumes:
      - /:/rootfs:ro
      - /var/run:/var/run:ro
      - /sys:/sys:ro
      - /var/lib/docker/:/var/lib/docker:ro

  prometheus:
    image: prom/prometheus
    ports: ["9090:9090"]
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml
      - ./rules.yml:/etc/prometheus/rules.yml
    command: --config.file=/etc/prometheus/prometheus.yml

  alertmanager:
    image: prom/alertmanager
    ports: ["9093:9093"]
    volumes:
      - ./alertmanager.yml:/etc/alertmanager/alertmanager.yml

  grafana:
    image: grafana/grafana
    ports: ["3000:3000"]

  loki:
    image: grafana/loki:3.0.0
    ports: ["3100:3100"]
    command: -config.file=/etc/loki/local-config.yaml

  promtail:
    image: grafana/promtail:3.0.0
    volumes:
      - ./promtail-config.yml:/etc/promtail/config.yml
      - /var/log:/var/log
    command: -config.file=/etc/promtail/config.yml

Jagu's Tip: One file, one command — docker compose up -d. That's the SRE way.

📊 The Unified Dashboard

One Grafana dashboard with three rows:

  • Row 1 — Host (USE): CPU %, Memory used, Disk I/O, Network.
  • Row 2 — Containers: per-container CPU and memory via cAdvisor.
  • Row 3 — Logs: a Loki log panel showing {job="varlogs"} in real time.
# Container CPU panel
sum(rate(container_cpu_usage_seconds_total{name!=""}[5m])) by (name) * 100

# Memory used panel
node_memory_MemTotal_bytes - node_memory_MemFree_bytes \
  - node_memory_Buffers_bytes - node_memory_Cached_bytes

Correlation superpower: When CPU spikes, open Loki Explore for the same time window and query {job="varlogs"} |= "ERROR". The metric says when, the log says why.

🌍 Real-World Example

Booking.com: Their SRE team runs thousands of services on a unified observability platform. When a flash-sale page starts failing, three things happen in parallel: a p99 latency alert fires to the on-call, the logs show a specific dependency timing out, and the trace shows exactly which request path hit it. This "metrics → logs → traces" flow turns a potential 45-minute incident into a 7-minute resolution.

That exact workflow is what your Day 80 project practices — at laptop scale! 🏆

🚫 Common Misconceptions
  • "Observability is too heavy for one machine." This entire stack runs on a laptop — that's the point of the lab.
  • "One tool can do it all." Even the LGTM stack uses 3+ tools; pick the right tool per pillar.
  • "If I build it, the team will use it." Dashboards die without runbooks and alert ownership. Culture matters.
  • "Alerting = dashboards." Dashboards show state; alerts change behaviour. You need both.

⚡ Quick Summary
  • One compose file runs the full observability platform (7 services).
  • Metrics: Node Exporter + cAdvisor → Prometheus → Grafana.
  • Logs: Promtail → Loki → Grafana Explore.
  • Alerts: rules.yml → Prometheus → Alertmanager → webhook.
  • Correlate: metric says when, log says why, trace says where.
  • Document runbooks — an unowned alert is just noise.
