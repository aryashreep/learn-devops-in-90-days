            └───────────────┘

Promtail watches files, adds labels (job, host, level), and pushes batches to Loki. Loki stores them compressed and indexes only the labels — that's why it's so cheap.

⚖️ Compare: Loki vs ELK

ELK Stack

  • Full-text indexes every word — huge storage.
  • Heavy: Elasticsearch + Logstash + Kibana.
  • Great for deep text search & analytics.
  • Expensive to run at scale.

Loki

  • Indexes labels only — stores raw lines compressed.
  • Lightweight, single binary, S3-compatible storage.
  • Perfect for operational logs & incidents.
  • Deeply integrated with Grafana & Prometheus labels.
📜 Promtail Config
server:
  http_listen_port: 9080
  grpc_listen_port: 0

positions:
  filename: /tmp/positions.yaml        # where it left off (resume!)

clients:
  - url: http://loki:3100/loki/api/v1/push

scrape_configs:
  - job_name: system
    static_configs:
      - targets:
          - localhost
        labels:
          job: varlogs
          __path__: /var/log/*.log

Jagu's Tip: The positions file is gold — Promtail remembers where it stopped, so restarts never lose logs!

🔎 LogQL — Querying Logs
# Step 1 — pick a stream by labels
{job="varlogs"}

# Step 2 — filter lines
{job="varlogs"} |= "ERROR"              # contains
{job="varlogs"} !~ "healthcheck"        # not matching regex

# Step 3 — aggregate
sum by (job) (count_over_time({job="varlogs"}[5m]))

# Step 4 — JSON parsing (structured logs)
{job="nginx"} | json | unwrap response_time

Remember: Label selector first {...}, then line filters |= "text", then aggregations.

📊 Query in Grafana
# Add data source: Loki → http://localhost:3100 → Save & Test

# Then go to: Explore (compass icon) → select Loki
# Query: {job="varlogs"} |= "error"
# Set the time range to "Last 1 hour" → Run query

🌍 Real-World Example

GitLab incident: A customer reported a payment failure. Engineers couldn't reproduce it, so they queried Loki across 200+ services in seconds:

{namespace="payments", env="prod"} |= "charge_failed" | json

Within a minute they saw a `timeout` message from the Stripe proxy on 2 specific pods — a flaky upstream, not a code bug. From "we can't find it" to "root caused" in 60 seconds. That's the power of centralized logs.

🚫 Common Misconceptions
  • "Loki can't do full-text search." True — and by design. Use ELK when you need it; use Loki for operational logs.
  • "Promtail is the only agent." Fluent Bit and Promtail both work — pick one for your team.
  • "Logs are cheap to keep forever." No — set retention or your storage bill explodes.
  • "Labels are optional." Bad labels = slow queries. Design label sets like you design indexes.

⚡ Quick Summary
  • Loki = cheap log storage, indexed by labels.
  • Promtail = log agent that discovers files & pushes them.
  • positions.yaml makes log shipping resumable.
  • LogQL = {labels} + |= "filter" + aggregations.
  • Grafana Explore is your log search box — with live tail.
  • Set retention policies; design labels before you ship.
