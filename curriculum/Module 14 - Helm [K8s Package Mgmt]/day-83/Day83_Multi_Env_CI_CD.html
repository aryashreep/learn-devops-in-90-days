   LOWEST  ┌─────────────────────────┐
           │  1. values.yaml         │  chart defaults
           ├─────────────────────────┤
           │  2. -f values-prod.yaml │  user files (in order)
           ├─────────────────────────┤
   HIGHEST │  3. --set image.tag=x   │  inline flags

# What actually wins for prod?
helm upgrade --install ai-bankapp ./ai-bankapp \
  -f values-prod.yaml --set image.tag=1.3.0
# → image.tag = 1.3.0 (--set beats the file)
🔄 Deploy per Environment
# Dev
helm upgrade --install ai-bankapp ./ai-bankapp \
  -f values-dev.yaml -n dev --create-namespace

# Staging
helm upgrade --install ai-bankapp ./ai-bankapp \
  -f values-staging.yaml -n staging --create-namespace

# Prod (with auto-rollback)
helm upgrade --install ai-bankapp ./ai-bankapp \
  -f values-prod.yaml -n prod --create-namespace --atomic

# Verify releases
helm list -A
helm history ai-bankapp -n prod

Jagu's Tip: --atomic = if the release fails, Helm rolls it back automatically. Mandatory for prod!

🤖 CI/CD with GitHub Actions
# .github/workflows/helm-deploy.yml
name: Deploy AI-BankApp

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: azure/setup-helm@v4
        with:
          version: v3.15.0
      - name: Lint
        run: helm lint ./ai-bankapp
      - name: Render (syntax + values check)
        run: helm template ai-bankapp ./ai-bankapp -f values-prod.yaml
      - name: Package
        run: helm package ./ai-bankapp -d ./dist
      - name: Push to OCI registry
        env:
          TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          helm registry login ghcr.io -u $GITHUB_ACTOR -p $TOKEN
          helm push ./dist/ai-bankapp-*.tgz oci://ghcr.io/aryashreep
      - name: Configure kubeconfig (cluster auth)
        env:
          KUBECONFIG_B64: ${{ secrets.KUBECONFIG_B64 }}
        run: |
          mkdir -p $HOME/.kube
          echo "$KUBECONFIG_B64" | base64 -d > $HOME/.kube/config
      - name: Deploy to prod
        run: helm upgrade --install ai-bankapp ./ai-bankapp \
               -f values-prod.yaml -n prod --create-namespace --atomic

Why this matters: every push = tested chart + versioned artifact + safe deploy. No more "works on my machine".

⚖️ Compare: Manual vs CI/CD Deploys

Manual Deploys

  • "I deployed from my laptop." — and nobody knows what's live.
  • Untested chart changes go straight to prod.
  • No audit trail, no versioned artifacts.
  • Rollbacks need heroics.

Pipeline Deploys

  • Every change: lint → template → package → deploy.
  • Chart is validated BEFORE it touches the cluster.
  • Artifacts versioned and pushed to a registry.
  • --atomic + helm rollback = boring recoveries.
🌍 Real-World Example

AI-BankApp Friday release: The team merges a fix to main. GitHub Actions fires: lint passes, helm template renders prod values correctly, the chart is packaged as ai-bankapp-0.2.0.tgz and pushed to ghcr.io, then helm upgrade --install rolls the release to revision 42 in the prod namespace.

Two minutes later the release is live and helm history ai-bankapp -n prod shows the whole story. If anything breaks — one command, one revision back. That's the final piece of your Helm mastery! 🏆

🚫 Common Misconceptions
  • "helm install works every time." Use helm upgrade --install — install fails on the 2nd run; upgrade --install is idempotent.
  • "Secrets are fine in values files." Values files get committed to Git! Use --set from CI secrets or external secrets.
  • "One values.yaml is enough." Environments differ (replicas, ingress, resources) — that's what override files are for.
  • "Charts must be pushed to a repo to be deployed." Local chart paths work great for CI; registries are for sharing.
🛠️ Try It Yourself
# 1. Create values-dev.yaml + values-prod.yaml (from values.yaml)
# 2. Render each environment and compare
helm template ai-bankapp ./ai-bankapp -f values-dev.yaml  | grep replicas:
helm template ai-bankapp ./ai-bankapp -f values-prod.yaml | grep replicas:

# 3. Deploy to two namespaces (with a cluster)
helm upgrade --install ai-bankapp ./ai-bankapp -f values-dev.yaml -n dev --create-namespace
helm upgrade --install ai-bankapp ./ai-bankapp -f values-prod.yaml -n prod --create-namespace
helm list -A

# 4. Test --set precedence
helm template ai-bankapp ./ai-bankapp -f values-prod.yaml --set replicaCount=10 | grep replicas:

# 5. Push a release and roll back
helm history ai-bankapp -n dev
helm rollback ai-bankapp 1 -n dev
⚡ Quick Summary
  • One chart + per-env values files = full environment control.
  • Precedence: values.yaml < -f file < --set.
  • helm upgrade --install + --atomic = safe, idempotent deploys.
  • Namespaces isolate environments; helm list -A sees all.
  • CI/CD: lint → template → package → push → deploy, every push.
  • Versioned artifacts + helm rollback = boring, reliable releases.
