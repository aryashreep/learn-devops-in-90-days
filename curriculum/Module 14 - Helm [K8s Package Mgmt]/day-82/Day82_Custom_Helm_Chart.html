📄 values.yaml — Sane Defaults
replicaCount: 2

image:
  repository: ghcr.io/aryashreep/ai-bankapp
  pullPolicy: IfNotPresent
  tag: "1.0.0"

service:
  type: ClusterIP
  port: 80

ingress:
  enabled: false
  host: bank.local

resources:
  limits:
    cpu: 500m
    memory: 512Mi
  requests:
    cpu: 250m
    memory: 256Mi

  enabled: false
  minReplicas: 1
  maxReplicas: 5
  targetCPUUtilizationPercentage: 80
🧩 Templating Language
# Access values
replicas: {{ .Values.replicaCount }}

# Built-in objects
name: {{ .Release.Name }}-{{ .Chart.Name }}
image: "{{ .Values.image.repository }}:{{ .Values.image.tag | default .Chart.AppVersion }}"

# Conditionals
{{- if .Values.ingress.enabled }}
apiVersion: networking.k8s.io/v1
kind: Ingress
{{- end }}

# Loops
{{- range .Values.extraEnv }}
- name: {{ .name }}
  value: "{{ .value }}"
{{- end }}

# Helpers & includes
labels:
  {{- include "ai-bankapp.labels" . | nindent 4 }}

# Maps as YAML
resources: {{- toYaml .Values.resources | nindent 10 }}

Pro tip: Always add | default ... to user-facing values so missing config never breaks the render.

🛠️ _helpers.tpl — Consistency
{{- define "ai-bankapp.name" -}}
{{- default .Chart.Name .Values.nameOverride | trunc 63 | trimSuffix "-" }}
{{- end }}

{{- define "ai-bankapp.fullname" -}}
{{- if .Values.fullnameOverride }}
{{- .Values.fullnameOverride | trunc 63 | trimSuffix "-" }}
{{- else }}
{{- $name := default .Chart.Name .Values.nameOverride }}
{{- if contains $name .Release.Name }}
{{- .Release.Name | trunc 63 | trimSuffix "-" }}
{{- else }}
{{- printf "%s-%s" .Release.Name $name | trunc 63 | trimSuffix "-" }}
{{- end }}
{{- end }}
{{- end }}

{{- define "ai-bankapp.labels" -}}
helm.sh/chart: {{ printf "%s-%s" .Chart.Name .Chart.Version }}
app.kubernetes.io/name: {{ include "ai-bankapp.name" . }}
app.kubernetes.io/instance: {{ .Release.Name }}
app.kubernetes.io/managed-by: {{ .Release.Service }}
{{- end }}

Jagu's Tip: Consistent labels = working selectors. Deployment labels MUST match Service selectors — that's why we centralize them in helpers!

✅ Lint, Render, Package
# Validate structure + templates (no cluster needed)
helm lint ./ai-bankapp

# Render manifests locally — inspect before installing!
helm template ai-bankapp ./ai-bankapp
helm template ai-bankapp ./ai-bankapp --set replicaCount=5

# Package into a distributable .tgz
helm package ./ai-bankapp
# → ai-bankapp-0.1.0.tgz

# Bonus: verify against a cluster (dry-run)
helm install ai-bankapp ./ai-bankapp --dry-run --debug
⚖️ Compare: Hardcoded vs Templated

Hardcoded YAML

  • Image, replicas, ports baked into 6 files.
  • Every env change = edit + copy + pray.
  • Labels drift → broken selectors.
  • No validation, no packaging.

Templated Chart

  • One chart, values drive everything.
  • dev/prod = different values files.
  • Helpers guarantee consistent labels.
  • helm lint + helm template catch mistakes.
🌍 Real-World Example

AI-BankApp team onboarding: Before charts, a new engineer needed a 3-page wiki to deploy AI-BankApp locally — and dev/staging configs were always "slightly different". After Day 82's chart, onboarding is:

git clone ... && helm install ai-bankapp ./ai-bankapp -f values-dev.yaml

Same chart, different values file. That's why companies like GitLab, Datadog, and Grafana ship their own Helm charts — one artifact, every environment.

🚫 Common Misconceptions
  • "helm create output is production-ready." It's a starting point — you MUST review, trim, and harden it.
  • "Secrets belong in values.yaml." Never! Use --set, external secrets, or a secrets chart.
  • "helm template installs to the cluster." No — it only renders YAML locally. Perfect for CI validation.
  • "Templates are hard." You need ~6 constructs: values, if, range, default, include, toYaml. That's it.
