# 🗓️ Day 03 — Linux Commands Practice

Welcome to **Day 03** of the **#LearnDevOpsIn90Days** challenge 🚀

Today's goal is to **build your Linux command confidence**.

You will create a cheat sheet of commands focused on:

* Process management
* File system
* Networking troubleshooting

This is the command toolkit you will reuse for years.

# 🎯 Today's Goals

✅ Create a Linux commands cheat sheet grouped by category

✅ Cover process, file system, networking, and log commands

---

# 📌 Tasks for Today

## 1️⃣ Create Your Cheat Sheet

Create a markdown file named `linux-commands-cheatsheet.md` or a hand-written cheat sheet (Recommended).

Your cheat sheet should be easy to scan during real troubleshooting.

---

## 2️⃣ Follow the Guidelines

Include **at least 20 commands** with one-line usage notes, distributed across these categories:

* **File System (5+):** `ls`, `cd`, `cp`, `mv`, `rm`, `find`, `chmod`, `chown`, etc.
* **Process Management (5+):** `ps`, `top`, `kill`, `pgrep`, `nice`, `nohup`, etc.
* **Networking (3+):** `ping`, `ip addr`, `dig`, `curl`, `ss`, `netstat`, etc.
* **Logs & Monitoring (3+):** `journalctl`, `tail`, `less`, `dmesg`, `watch`, etc.
* **Miscellaneous (4+):** `grep`, `awk`, `sed`, `xargs`, `wc`, `sort`, etc.

Group commands by category and keep it concise and readable.

# 🧠 Key Concepts Introduced Today

| Concept               | Meaning                                            |
| --------------------- | -------------------------------------------------- |
| File System Commands  | Navigate, create, move, and manage files/dirs      |
| Process Management    | View, control, and terminate running processes      |
| Networking Commands   | Diagnose connectivity, DNS, and port issues         |
| Log Inspection        | Read system and service logs for troubleshooting    |
| Text Processing       | Filter, search, and transform command output        |

# ⚙️ Why This Matters for DevOps

Real production issues are solved at the command line.

The faster you can inspect logs and network issues, the faster you can:

* Restore service
* Reduce downtime
* Gain trust as an operator
