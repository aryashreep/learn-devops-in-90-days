🎯 Why a Battle Test?

DevOps engineers are alerted anytime in production. Any service is down, permissions are incorrect, process is hanging — You have to fix it without panic in the terminal. This simulates a lab!

🔧 The 5 Broken Scenarios
1. 🕵️ The Ghost File

A file .hidden_key is hidden somewhere /etc. Jagu's exact path is unknown.

Skill: find / locate commands

$ find /etc -name ".hidden_key" -type f 2>/dev/null
2. 🔒 Permission Hell

/tmp/fix_me.sh exists but won't execute. No 777 allowed!

Skill: chmod with specific permissions

$ chmod 755 /tmp/fix_me.sh
3. 👑 Ownership Crisis

/opt/app-data is owned by nobody. Wrong owner!

Skill: chown / chgrp

$ sudo chown -R $(whoami):$(id -gn) /opt/app-data
4. 🧟 The Resource Hog

One sleep 9999 process is zombie ban. PID dhundho aur maaro!

Skill: ps, grep, kill

$ ps aux | grep "sleep 9999" | grep -v grep | awk '{print $2}' | xargs kill
5. 📋 The Log Overflow

/var/log/dummy.log mein 1000 lines of junk. Sirf last 10 lines dikhao.

Skill: tail

$ tail -10 /var/log/dummy.log
🧠 Troubleshooting Mindset

The DevOps Debug Flow:

  1. 1️⃣ READ — Error message carefully padho (loga, stderr)
  2. 2️⃣ INVESTIGATE — Status check karo (ls -la, ps, df -h)
  3. 3️⃣ ANALYZE — Root cause identify karo (grep, journalctl)
  4. 4️⃣ FIX — Minimal change apply karo (chmod, kill, rm)
  5. 5️⃣ VERIFY — Confirm the fix works (test again)
❓ Battle Test Mini Quiz

1. Why use Find command mein "2>/dev/null"?

A) To speed up the output B) To hide permission denied errors C) To delete the file D) To send network request

2. Kill command se process terminate nahi ho raha — next step?

A) kill -9   B) rm -rf   C) systemctl restart   D) reboot

3. Script is not executing despite 755 permissions. What to check?

A) File content   B) Shebang (#!) line   C) Network   D) Disk space

✅ Answer Key

1-B (Hide permission denied noise while searching)  |  2-A (SIGKILL — force terminate)  |  3-B (Missing or wrong interpreter path)
