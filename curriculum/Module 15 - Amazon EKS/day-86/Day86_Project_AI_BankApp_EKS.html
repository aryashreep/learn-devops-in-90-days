📜 The Core Manifest
# namespace.yaml
apiVersion: v1
kind: Namespace
metadata: { name: ai-bank }
---
# deployment.yaml — with readiness probe for zero-downtime
apiVersion: apps/v1
kind: Deployment
metadata: { name: ai-bankapp, namespace: ai-bank }
spec:
  replicas: 2
  selector: { matchLabels: { app: ai-bankapp } }
  strategy:
    type: RollingUpdate
    rollingUpdate: { maxUnavailable: 0, maxSurge: 1 }
  template:
    metadata: { labels: { app: ai-bankapp } }
    spec:
      serviceAccountName: ai-bankapp-sa      # IRSA for Secrets Manager
      containers:
        - name: app
          image: aryashreep/ai-bankapp:1.4.0
          ports: [ { containerPort: 80 } ]
          readinessProbe:
            httpGet: { path: /health, port: 80 }
            initialDelaySeconds: 5
            periodSeconds: 5
          livenessProbe:
            httpGet: { path: /health, port: 80 }
            initialDelaySeconds: 15
            periodSeconds: 10
          envFrom:
            - secretRef: { name: ai-bank-db-secret }
          resources:
            requests: { cpu: 250m, memory: 256Mi }
            limits:   { cpu: 500m, memory: 512Mi }
---
# service.yaml
apiVersion: v1
kind: Service
metadata: { name: ai-bankapp, namespace: ai-bank }
spec:
  selector: { app: ai-bankapp }
  ports: [ { port: 80, targetPort: 80 } ]

Pro pattern: maxUnavailable: 0, maxSurge: 1 + readiness probe = old pod stays serving until the new one is Ready. Zero downtime!

📈 Scaling: Pods AND Nodes
# hpa.yaml — scale PODS on CPU
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata: { name: ai-bankapp-hpa, namespace: ai-bank }
spec:
  scaleTargetRef: { apiVersion: apps/v1, kind: Deployment, name: ai-bankapp }
  minReplicas: 2
  maxReplicas: 10
  metrics:
    - type: Resource
      resource:
        name: cpu
        target: { type: Utilization, averageUtilization: 60 }

# Cluster Autoscaler — scale NODES (Helm)
helm repo add autoscaler https://kubernetes.github.io/autoscaler
helm install cluster-autoscaler autoscaler/cluster-autoscaler \
  --namespace kube-system \
  --set autoDiscovery.clusterName=ai-bank-cluster \
  --set awsRegion=us-east-1
  • HPA: more pods when CPU > 60%.
  • Cluster Autoscaler: more EC2 nodes when pods can't fit.
  • Both together = true elastic capacity.
🔐 Secrets: AWS Secrets Manager + IRSA

Never put DB passwords in Git. Store them in AWS Secrets Manager and let the pod read them with its own IAM identity (IRSA from Day 84):

# 1. Create the secret (one-time)
aws secretsmanager create-secret \
  --name ai-bank/db \
  --secret-string '{"DB_PASSWORD":"SuperSecret123!"}'

# 2. Grant the app's ServiceAccount read access (IRSA)
eksctl create iamserviceaccount \
  --cluster ai-bank-cluster --namespace ai-bank \
  --name ai-bankapp-sa \
  --attach-policy-arn arn:aws:iam::aws:policy/SecretsManagerReadWrite \
  --approve

# 3. External Secrets Operator syncs it to a K8s Secret
kubectl apply -f - <<'EOF'
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata: { name: ai-bank-db, namespace: ai-bank }
spec:
  secretStoreRef: { name: aws-secretsmanager, kind: SecretStore }
  target: { name: ai-bank-db-secret }
  data:
    - secretKey: DB_PASSWORD
      remoteRef: { key: ai-bank/db, property: DB_PASSWORD }
EOF
🌍 Ingress with TLS
# Request an ACM certificate in the console (us-east-1) for app.example.com,
# then attach it to the ALB Ingress:
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: ai-bankapp
  namespace: ai-bank
  annotations:
    kubernetes.io/ingress.class: alb
    alb.ingress.kubernetes.io/scheme: internet-facing
    alb.ingress.kubernetes.io/listen-ports: '[{"HTTPS":443}, {"HTTP":80}]'
    alb.ingress.kubernetes.io/certificate-arn: arn:aws:acm:us-east-1:ACCOUNT:certificate/xxxx
    alb.ingress.kubernetes.io/ssl-redirect: "443"
spec:
  rules:
    - host: app.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: ai-bankapp
                port: { number: 80 }

Result: HTTPS on the ALB, HTTP auto-redirected to 443, cert managed by ACM (auto-renewed).

📊 Observability
  • CloudWatch Container Insights: enable once per cluster — pod/node metrics + logs in CloudWatch.
  • Prometheus + Grafana: the SRE way (Module 13!) — deploy via Helm, scrape with the Prometheus add-on.
  • Alerting: alarms on CPU, 5xx from the ALB, and failed pods (SNS → Slack).
# One command to enable Container Insights
eksctl utils update-cluster-logging \
  --enable-types=all --cluster ai-bank-cluster --region us-east-1
🌍 Real-World Example

SaaS → the "auto-scaling win": A B2B SaaS ran a Kubernetes cluster with fixed nodes and manual deploys — a marketing spike melted the nodes and deploys took an hour of careful YAML surgery. They rebuilt on EKS exactly like this lesson: HPA for pods, Cluster Autoscaler for nodes, Secrets Manager for credentials, ALB + ACM for TLS, and rolling updates. Spike traffic now scales up and down automatically; deploys are `kubectl rollout restart` — zero downtime, every time.

🚫 Common Misconceptions
  • "One big cluster for everything, one namespace for prod." Use separate namespaces (and ideally clusters) per environment.
  • "HPA is enough." HPA scales pods, not the underlying nodes — pair it with Cluster Autoscaler.
  • "Secrets in ConfigMaps are fine." ConfigMaps are NOT encrypted — use Secrets Manager/External Secrets.
  • "TLS is an app problem." The ALB terminates TLS — your pods can stay plain HTTP internally.

⚡ Quick Summary
  • Production EKS = Namespace + Deployment + Service + HPA + Cluster Autoscaler + Secrets + ALB/TLS + monitoring.
  • HPA scales pods; Cluster Autoscaler scales nodes; both = elasticity.
  • Secrets live in AWS Secrets Manager, injected via IRSA / External Secrets.
  • ALB + ACM = free TLS termination and HTTP→HTTPS redirect.
  • Readiness probes + rolling updates = zero-downtime deploys.
