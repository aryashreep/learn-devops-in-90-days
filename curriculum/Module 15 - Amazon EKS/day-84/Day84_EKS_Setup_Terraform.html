🏗️ What is Amazon EKS?

Amazon EKS (Elastic Kubernetes Service) = certified Kubernetes, run as a managed service on AWS. You bring the workloads; AWS keeps the control plane alive.

┌────────────────────────────────────────────────────┐
│  EKS CONTROL PLANE (managed by AWS, HA across AZs) │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐          │
│  │ API srvr │  │  etcd    │  │ kube-ctl │  ...     │
│  └──────────┘  └──────────┘  └──────────┘          │
└───────────────────────┬────────────────────────────┘
                        │ API calls
        ┌───────────────┼───────────────────┐
        ▼               ▼                   ▼
  ┌─────────────┐ ┌─────────────┐  ┌──────────────┐
  │ Node group 1│ │ Node group 2│  │ Fargate pods │
  │ EC2 workers │ │ EC2 workers │  │ (serverless) │
  └─────────────┘ └─────────────┘  └──────────────┘
        ▲               ▲                   ▲
        └─────── all inside YOUR VPC ───────┘
  • Control plane: API server + etcd — fully managed, patched, and scaled by AWS.
  • Node groups: EC2 instances that run your pods (managed or self-managed).
  • Fargate profiles: run pods WITHOUT any nodes at all (serverless).
  • VPC: everything runs inside subnets in your own VPC.
⚖️ Compare: eksctl vs Terraform

eksctl (CLI)

  • Fastest way to get a cluster (2 minutes).
  • Great for demos, labs, and local experiments.
  • Config is YAML, but not versioned state.
  • Limited drift detection & no plan step.

Terraform

  • Declarative, plan before apply.
  • Versioned state + real drift detection.
  • Same code creates VPC, nodes, IAM, add-ons.
  • The standard for production platforms.

Jagu's Rule: eksctl for exploring, Terraform for everything that lives longer than a day! 🏗️

🔐 IAM & OIDC (IRSA)

Kubernetes pods need AWS permissions (S3, DynamoDB, etc.). The secure pattern is IRSA — IAM Roles for Service Accounts:

# 1. Enable the OIDC provider for your cluster
eksctl utils associate-iam-oidc-provider --cluster demo --approve

# 2. Create a ServiceAccount bound to an IAM role
eksctl create iamserviceaccount \
  --cluster demo \
  --namespace ai-bank \
  --name ai-bankapp-sa \
  --attach-policy-arn arn:aws:iam::aws:policy/AmazonS3ReadOnlyAccess \
  --approve
  • The cluster publishes an OIDC discovery endpoint; the IAM role trusts it.
  • Tokens are short-lived (1h) — never hardcode AWS keys in pods.
  • One IAM role per service account = least privilege.
📦 Terraform EKS Module

The community-standard terraform-aws-modules/eks gives you a production-ready cluster in ~40 lines:

provider "aws" {
  region = "us-east-1"
}

module "eks" {
  source  = "terraform-aws-modules/eks/aws"
  version = "~> 20.0"

  cluster_name    = "ai-bank-cluster"
  cluster_version = "1.31"
  vpc_id          = module.vpc.vpc_id
  subnet_ids      = module.vpc.private_subnets

  eks_managed_node_groups = {
    workers = {
      desired_size   = 2
      min_size       = 1
      max_size       = 5
      instance_types = ["t3.medium"]
    }
  }
}

output "cluster_endpoint" { value = module.eks.cluster_endpoint }
output "cluster_name"     { value = module.eks.cluster_name }

Then: terraform init → terraform plan → terraform apply -auto-approve (~15 min).

🔌 Connect Your kubectl
# Merges EKS credentials into ~/.kube/config
aws eks update-kubeconfig --region us-east-1 --name ai-bank-cluster

# Verify
kubectl cluster-info
kubectl get nodes -o wide
kubectl get pods -A

Note: EKS uses aws-iam-authenticator (or the newer aws eks plugin) — your IAM user/role becomes the Kubernetes admin via aws-auth ConfigMap.

🌍 Real-World Example

Fintech → the "no-master-nightmares" story: A payments startup spent months babysitting self-managed Kubernetes on EC2 — API server upgrades broke twice a year and etcd backups were a nightmare. They migrated to EKS: AWS took over the control plane, the team moved from "infra firefighting" to shipping features, and their Terraform module let them recreate staging + prod clusters in under 20 minutes each. Quarterly upgrades became a 30-minute terraform apply with a version bump.

🚫 Common Misconceptions
  • "EKS is just Kubernetes I host on EC2." No — AWS manages the control plane; you manage only nodes/workloads.
  • "EKS is expensive for learning." The control plane costs ~$0.10/hr, but you can use managed node groups + spot instances or Fargate to keep it cheap, and delete it after labs.
  • "I must use eksctl." eksctl is a convenience tool, not a requirement — Terraform is the production-grade choice.
  • "Pods get the same access as my EC2 instance." With IRSA, each pod gets its OWN identity. Never share instance roles.
🛠️ Try It Yourself
# 1. Pre-reqs
aws configure            # set credentials + region
eksctl version
kubectl version --client
terraform version

# 2. Quick cluster (eksctl path — great for a first taste)
eksctl create cluster \
  --name demo --region us-east-1 \
  --nodegroup-name workers \
  --node-type t3.medium --nodes 2 --managed

# 3. Connect
aws eks update-kubeconfig --region us-east-1 --name demo

# 4. Verify
kubectl get nodes -o wide
kubectl get pods -A

# 5. Terraform path (the production way) — follow the module above

# 6. Clean up when done!
eksctl delete cluster --name demo --region us-east-1
