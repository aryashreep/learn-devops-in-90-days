1. LEARNING OBJECTIVES & WHY SEEKHEIN

Microservices communication setup mein manual configuration complex hai. Docker Compose network parameters automatically coordinate karta hai. Is model ko seekhna scalable app deployment ke liye essential hai.

  • Understand dynamic name-based DNS resolution in Docker Compose.
  • Utilize depends_on and connection retry configs.
  • Setup isolated multi-tier networks (e.g. backend-db separated from public frontend).
🌐 DNS Resolution in Docker Compose

When you start a Compose file, Docker creates a default network. Every service uses its service name as the hostname. Docker's internal DNS resolver handles mapping dynamically!

Network Isolation Setup

[Public Traffic] -> Web App (frontend-net)
Web App (backend-net) <---> Database (backend-net) [No Public Access]

⚖️ Comparison: Shared default network vs. Isolated custom networks
Default Network

All services are on one bridge. Database is accessible by frontend and potentially exposed if port mapping is misconfigured.

VS
Isolated custom networks

Database is on a private backend network. Only backend application can talk to it, securing database queries from external breaches.

🎬 Real World Troubleshooting: DB Startup Lag

The backend start hote was crashing because the database boot-up was taking 5 seconds to complete. When depends_on is used it only checks the container status, not the internal health. The problem was solved by configuring Healthcheck!
