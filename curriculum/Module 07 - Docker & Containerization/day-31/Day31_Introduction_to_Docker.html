What will we learn today?

⚖️ VMs vs Containers
Virtual Machine
  • Includes full Guest OS (GBs)
  • Boot time: minutes
  • Resource: Heavy (Hypervisor)
  • Isolation: Strong (separate kernel)
  • Portability: Slow to transfer
VS
Container
  • Shares Host OS kernel (MBs)
  • Boot time: seconds
  • Resource: Lightweight (Docker Engine)
  • Isolation: Process-level (namespaces)
  • Portability: Fast, pull/push layers

Client: CLI commands | Daemon: Background service | Registry: Image storage (Docker Hub)

⌨️ Essential Docker Commands
# Check installation
docker --version
docker info

# Working with images
docker pull nginx:alpine      # Download image
docker images                 # List local images
docker rmi nginx:alpine       # Remove image

# Running containers
docker run hello-world        # Run & auto-remove
docker run -it ubuntu bash    # Interactive shell
docker run -d -p 8080:80 nginx # Detached with port

# Container management
docker ps                     # Running containers
docker ps -a                  # All containers
docker stop <container>       # Graceful stop
docker rm <container>         # Remove container

# System
docker system df              # Disk usage
docker system prune           # Clean unused
💡 Real-World: Why Docker?

Scenario: You have written a Node.js app which is running correctly on the local machine. Deployed on Production Ubuntu server to \`glibc version\` mismatch ka error is coming. The app + dependencies are packed together in the Docker container — there will be no version mismatch!

DevOps Mantra: Changing "It works on my machine" to "It works everywhere" — this is Docker's promise.
